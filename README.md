**使い方：** 各ファイルの先頭に【種類】【内容】【まずやること】【やってみよう】が書いてあります。そのまま実行するだけでなく、**値を変える → 結果を予想する → 実行して確かめる** を繰り返してください。
「作成」のファイルは、`/* ここを書き換える */` の部分を自分で書いて完成させます。

## よく使うコマンド

```
gcc 03-define-pi.c -o 03-define-pi          （いつものコンパイル：4つの工程をまとめて実行）
./03-define-pi

gcc -E 03-define-pi.c -o 03-define-pi.i     （プリプロセスだけ実行して、結果を .i ファイルに保存）
tail -n 8 03-define-pi.i                      （結果の最後の8行だけ表示）
```

| コマンド | どこまで実行するか | できるファイル |
|---|---|---|
| `gcc -E ファイル.c -o ファイル.i` | プリプロセッサまで | #include や #define を置き換えたソース |
| `gcc -S ファイル.i -o ファイル.s` | コンパイラまで | アセンブリ言語 |
| `gcc -c ファイル.s -o ファイル.o` | アセンブラまで | オブジェクトファイル（機械語） |
| `gcc ファイル.o -o ファイル` | リンカまで | 実行ファイル |

## 注意

- **`gcc -E` で作る .i ファイルは「結果」です。** 見るだけのファイルなので、編集したり #include したりしないでください（中に stdio.h の中身も main も全部入っているので、#include すると二重になってエラーになります）。#include で読み込む「材料」は sample.txt です。

- Mac で `gcc` と打つと、中身は Apple の clang というコンパイラが動きます（`gcc --version` で確認できます）。オプションは同じように使えます。
- `gcc -E` の結果（stdio.h の中身など）や、アセンブリ言語の見た目は、パソコンの種類によって違います。隣の人と画面が違っても問題ありません。
- 「作成」のファイルは、書き換える前でもコンパイル・実行できます（結果は 0 などになります）。
